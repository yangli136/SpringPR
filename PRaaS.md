# Spring based Paved Road on Cloud PaaS + DBaaS (PRaaS)
---
---

## Problem Statement
---

Spring based Paved Road (SpringPR) is an (Abc Way - hopefully) framework
provides an opinionated prescription of out-of-box non-functional features
implemented over Spring Boot framework.


SpringPR follows non-invasive programming style and industry standards
vigorously to make it future proof and facilitate a much smoother migration
experience.


We’d like to propose a joint effort between the Cloud Engineering and
SpringPR team to provide an enterprise solution similar to SaaS without
business functions (PRaaS?).


For example, if an application consumes messages from a Kafka topic then
persists it to a Cassandra data store, from day one, the dev team should be
able to get the SpringPR components with non-functional features that work
with both Cassandra and Kafka and other core non-functional features
(Availability, Scalability, Resiliency, Security), the SpringPR also has been
deployed to eCP with Hydra, Cassandra, Kafka instances ready from E1 to E3,
along with CI/CD, built in integration, performance testing mechanisms etc..

## Benefits
---

Promoting PRaaS across Abc Technology, an industry-standards-based
solution that has built-in enterprise grade non-functional features
(Availability, Scalability, Resiliency, Security, Performance), we may realize
the following Benefits:
- Significantly diminishing non-cloud-friendly implementations and reducing
support effort and cost.
- Significantly reducing communication effort and friction between support
teams and dev teams.
- Significantly increasing knowledge sharing across Abc Technology.
- Significantly reducing migration cost in future.
- Significantly reducing application incidents with the aid of quality PRaaS
features (enterprise grade error handling, better resiliency etc.).
- Significantly increasing speed of delivery.
